// export/cli.ts: the one door into export/ (SKETCH). A person and an agent type the same
// commands; --json prints one JSON object per command for an agent (and, later, for the MCP
// server, export/mcp.ts, which calls the same four functions below and nothing else).
//
//   bun run export web [--project character]          check, bundle, write out/web/<game>/
//   bun run export verify [out/web/character]         re-read a folder: whole? laws hold?
//   bun run export serve  [out/web/character]         serve it locally with the contract's headers
//   bun run deploy vercel|vps|itch [--project x]      export, then publish a PREVIEW; prints its link
//   bun run promote vercel|vps|itch <build-id>        make that build live (a person, in a terminal)
//   bun run rollback vercel|vps|itch                  promote the build before the live one
//   bun run deploys vercel|vps|itch                   list builds, newest first, the live one marked
//
// package.json:
//   "export":   "bun export/cli.ts export",
//   "deploy":   "bun export/cli.ts deploy",
//   "promote":  "bun export/cli.ts promote",
//   "rollback": "bun export/cli.ts rollback",
//   "deploys":  "bun export/cli.ts deploys"
//   ("build": "bend index.html -o dist" stays as the editor demo build (shared script, not ours to remove);
//    `export web` is the one way to build a GAME.)
//
// Limits now:
// - Who is a person: promote asks for the build id to be typed back on an interactive terminal
//   (process.stdin.isTTY). An agent with a pty could still type it; the real wall is the host's
//   token scope (see RATIONALE: open questions).
