// publish/server.ts: the publish protocol's server (SKETCH, new in v2). HANDS ONLY: HTTP, disk,
// sha256, gzip sizes, symlinks, the flock and the log. Every answer comes from publish/service.bend.
//
// One program, two modes, chosen by its config file (/srv/ogw/server.json), never by code:
//   { "mode": { "Team": { "creator": "ogw" } }, "play": "<play domain>", "api": "api.<service domain>", "port": 7400 }
//   { "mode": "Service", ... }   (adds /v1/login/*, approvals and the service's Bend pages)
//
// It runs on the VPS behind Caddy (sketch/example/Caddyfile): Caddy serves the games' files straight
// from /srv/ogw/sites/ (this process is never on the path of a player's request) and proxies
// api.<service> to this process. A process crash stops publishing, never playing.
//
// Deployed as ONE file: `bun build publish/server.ts --target bun --outfile out/publish-server.js`
// compiles the Bend modules in through the same loader as everything else, so the VPS needs bun and
// nothing from the repo, no `bend`, no ../bend.
//
//   bun out/publish-server.js serve                  answer the protocol
//   bun out/publish-server.js caddyfile              print Sv.caddyfile(...) for a person to install once
//   bun out/publish-server.js person <name>          (Team) add a person: prints their key once and
//                                                    asks for their point secret twice (stored hashed)
//   bun out/publish-server.js reconcile              rebuild sites/ from releases/ and channels/
//
// Limits now:
// - Approvals (Service mode) need the service's own Bend pages (login, approve): built in the
//   service slice, from Bend-UI's Web.bend like the editor's. Team mode has none.
// - Requests are checked for the protocol header and a key before anything is read from disk.
