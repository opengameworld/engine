# Who a creator is to a publish host, and what each credential may do. (SKETCH, new in v2)
#
# Two credentials, split by type, so the review's rule is a shape and not a check someone forgets:
#
#   a KEY (bearer, in env or a 0600 file): read, upload releases, move OPEN channels; a person's key
#     also mints and revokes machine keys. No key, of anyone, moves a guarded pointer by itself.
#   PRESENCE (proof a person is here now): needed, with the typed confirmation, to move a guarded
#     pointer (live). On the VPS: the person's point secret, typed at the prompt, never stored by the
#     client. On the service: an approval the person gives on the service's page in their browser
#     (logged in there), the same flow as Bend's own `bend login` (start -> verify_url -> poll, read
#     this session in ../bend/bend2/main.ts cli_login).
#
# From Coolify (read per grounding: PersonalAccessToken, ApiAbility): keys are scoped to a team
# (here: a creator) and to some games, expire, can be paused and rotated; the secret carries a
# checksum so a typo is told apart from a revoked key; only its hash is stored. From CapRover: a
# creator's key version, bumped by revoke-all. From butler: env beats file, and CI never logs in.
#
# Limits now:
# - No per-channel scopes: a machine key moves every Open channel of its games.
# - Expiry is in whole days; a key expires at the start of that day, server time.

type Holder is Data:
  Person{name: String}
  Agent{}         # an AI agent: made by a person for one task
  Robot{}         # CI

# Which games a key reaches, inside its creator.
type Reach is Data:
  AllGames{}
  Only{games: List<&2, String>}

type PubKey is Data:          # not `Key`: a Base constructor (CATCHES N1)
  PubKey{
    id: String,          # "k_" ++ 8 hex, public, shown in history
    creator: String,
    holder: Holder,
    reach: Reach,
    expires: U32,        # day number (days since 2026-01-01); 0 = never (person keys on the VPS only)
    paused: Bool,
    version: U32         # must equal the creator's version (revoke-all bumps it)
  }

type Presence is Data:
  Absent{}
  Typed{secret_ok: Bool, confirm: String}       # VPS: the hands compared the typed secret's hash
  Approved{person: String, confirm: String}     # service: approved on the service's page

# What a request wants to do.
type Act is Data:
  Read{}
  Upload{game: String}
  MoveOpen{game: String}
  MoveGuarded{game: String}
  Mint{holder: Holder}
  Revoke{}

type Denied is Data:
  NotAPerson{}            # a machine key asked for a person's act
  NeedsPresence{}         # a guarded move without a person present
  BadSecret{}
  BadConfirm{want: String}
  Expired{}
  Paused{}
  Revoked{}               # key version behind the creator's
  OtherCreator{}
  NotThisGame{game: String}
  NoPersonsMintPersons{}  # person keys come only from login (service) or the box (VPS)

type Verdict is Data:
  Allowed{}
  No{why: Denied}

# ---------- Secrets ----------
#
# "ogw" ++ kind ++ "_" ++ 40 random [a-zA-Z0-9] ++ "_" ++ 6 hex of crc32(the 40):
#   kind "p" person, "a" agent, "r" robot   ->  ogwa_x9...Q_1f2e3d
# The prefix lets secret scanners and people see what leaked; the checksum tells a typo (BadFormat,
# answered without a lookup) from a dead key. Randomness and hashing are the hands'; the format and
# its parse are here.

  BadFormat{}
  BadChecksum{}
